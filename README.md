# Arcus Maker / Lighter Taker

Independent strategy runner: resting **Arcus PostOnly** quotes, confirmed incremental fills, and opposite **Lighter market/IOC** hedges. The default `paper` and `monitor` modes run the full strategy on public market data with a deterministic simulation. They do not load `.env`, construct a signer, call account endpoints, or send live orders.

Python 3.12; install the pinned runtime in this project:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-lighter-arcus.txt
bash start.sh paper --duration-seconds 86400
# monitor is the same complete public-data paper strategy
bash start.sh monitor --duration-seconds 86400
```

BTC, ETH, SOL and HYPE are enabled in `config/arbitrage/arbitrage_segmented.yaml`; BNB is disabled and is never subscribed by the maker runner. `enabled: false` does not fall back to default configuration. Disabled/foreign existing inventory or unresolved orders block live startup. Profiles are immutable while a process owns orders.

## Quotes and risk

Percent values use `0.005 = 0.005%`. Each symbol centers quotes on `b = EMA(100 * (Arcus mid / Lighter mid - 1))`, using the existing time-weighted EMA algorithm with a configurable `maker.basis_ema_seconds: 30` time constant. Fresh books seed the first EMA sample immediately. New opening and closing quotes require the configured warmup (default 60 seconds) of valid two-venue observation, independently of the EMA time constant. Invalid data pauses admission; the timeout and reset rules below distinguish a short same-socket outage from a new feed generation. Recovery, cancellations, existing-fill hedging and reconciliation continue during warmup. The separate 30-second startup subscription deadline does not wait for warmup. EMA state is not persisted. Arcus buy/sell quotes use `Lighter executable side * (1 + (b - side * threshold)/100)`, where buy side is +1 and sell side is -1. Opening grid and closing thresholds share this center. Buy prices round down and sells up; a crossing quote rests at the closest legal tick below the Arcus ask or above its bid, including tick-tier boundaries. Entry quotes satisfy Arcus minimum size and max($5, current Arcus minimum notional).

Orders reprice when the basis-adjusted fair anchor movement is strictly greater than `0.005%`, or age reaches 30 seconds. Replacement cycles are limited to two per second per symbol across both sides. Cancellation must reach authoritative terminal state before replacement. Risk cancellations bypass the quote throttle. Flat inventory offers both opening directions; the first fill cancels the reverse opening quote. Late opposite fills are still journaled and hedged against net inventory. Opening and closing quotes can coexist; close reservations cannot exceed paired confirmed inventory. Opening quantity is the smaller of one layer and the remaining segment cap after absolute Arcus inventory and every active unfilled opening reservation, floored to the common venue step. Flat one-segment quotes retain the half-layer rule. Capacity and capital are rechecked under the capital lock and immediately before signing. Close planning runs first; when no legal opening fits, a legal paired layer tail can close first. A tail below the maker size/notional minimum or common step is retained with a deduplicated `close_tail_deferred` reason, and a regular legal close remains available. Quantities are never rounded up to meet a minimum.

Normal closing quotes additionally use `grid_config.min_close_profit: 0.01` (0.01%, divided by 100 once) and `close_floor_timeout: 600` seconds, merged from defaults and optional per-symbol overrides. Remaining opening fills are consumed FIFO. For the proposed legal closing quantity, only selected FIFO portions younger than their own opening maker-fill time plus the timeout contribute to the protection. Their quantity-weighted actual Arcus and Lighter opening execution averages are `A` and `L`. A long-Arcus close sells at least `A + current Lighter ask - L + A * min_close_profit / 100`; a short-Arcus close buys at most `A + current Lighter bid - L - A * min_close_profit / 100`. This is the combined two-leg estimate; it adds no separate Arcus break-even constraint or slippage buffer. The original EMA quote is moved only in the more conservative direction, then rounded to a legal passive tick.

Each opening lot expires independently at age >= timeout; adding inventory does not renew older lots. Expired portions do not subsidize younger portions. With no protected selected portion (or timeout zero), the original EMA close quote applies. A mixed-age order keeps its original legal quantity and one common price, so a younger portion can still constrain an older portion. Partial closes consume FIFO and trigger a new calculation for the remaining quantity; the estimate is for the proposed whole quantity and does not guarantee the target for every possible partial fill. Fees, funding and actual closing hedge slippage can reduce or reverse the estimated profit.

Unknown actual entry costs use the original EMA fallback for the affected selected portions. Each lot is split at actual opening hedge-fill coverage boundaries, including missing prices or uncovered ranges. Only fresh portions with both actual entry prices enter the weighted protection bound; unknown and expired quantities never dilute that bound. One common legal close price is the more conservative of the EMA quote and the known-cost bound. Actual costs and whole-order estimated PnL remain unknown where coverage is missing. Known maker-fill times still expire normally. If opening time/continuity is unavailable, a persisted first position observation (including reconciliation drift) retains explicitly unknown age/cost attribution across restart; a fresh position cannot inherit an older observation. The current FIFO and unsettled restoration undo are replayed once from committed journal events, then updated by indexed event ID; journal schema remains v3. Emergency restoration retains the original lot costs, FIFO order and opening times. Existing-fill hedging and recovery continue independently until the severe-failure manual-intervention lock described below; cancellation and authoritative observations remain available under that lock. Market changes, partial fills and expiry recheck resting close orders; unsafe quotes are canceled even when replacement throttles are exhausted, and a final synchronous check runs after the Arcus write lock/authentication waits before signing.

Each venue has a configurable 5000 USDC allocation and an economic gross exposure/equity ceiling of 2, with a 2% reserve. The shared capital check includes existing inventory, outstanding and unknown openings, and unresolved closing capacity; pending closes do not free opening capacity. Every active unfilled opening, including other symbols, is valued at the higher of its stored reservation and current two-venue asks; a missing market cannot release that reservation for admission. A 500 USDC uncovered-exposure limit also limits potential fills of outstanding quotes. Current quote sizes are conservative examples and do not automatically consume the account allocation.

Book validity requires a current-generation initialized snapshot, proven sequence continuity, a connected socket and actual received-frame age <= `risk.stale_book_seconds` (the current profile uses 5 seconds). Static prices remain valid with genuine inbound ACK/data/control PING/PONG frames; outbound sends never refresh liveness. A heartbeat never changes `Book.received`, its identity, sequence or paper depth. Public and maker-private sockets actively control-ping at half the stale threshold. Socket keepalive allows at least the stale threshold plus `maker.quick_resume_seconds` (default 10) for a response; admission/cancellation still reacts immediately at the stricter stale threshold. An invalid same-socket timeout shorter than quick-resume preserves EMA and completed readiness; incomplete warmup pauses during the outage. A longer timeout, sequence gap, reconnect or generation change restarts `maker.warmup_seconds` (default 60). Private reader exit invalidates readiness before connection cleanup, and a new private generation needs a fresh account subscription acknowledgement. Arcus `l2Orderbook` is a full snapshot: its last sequence may repeat or jump. Lighter forward deltas require `begin_nonce == previous nonce`; offset is monotone, never assumed contiguous. Public Lighter data uses the official unauthenticated `stream?readonly=true` entry; private/signing/REST endpoints remain unchanged.

A stale or outdated-generation book pauses admission and cancels makers only for that symbol; other valid warmed symbols can quote. True venue/private disconnects, UNKNOWN, unresolved cancellation and global capital/risk failures retain global cancellation protection. Inventory and reservations of stale symbols remain included in risk. Quote admission, hedging and pre-sign checks use the same received-frame validity contract. Every normal Arcus opening/closing maker rechecks current readiness after its write-lock/authentication waits before nonce/signing; closing makers also retain the FIFO price/capacity guard. A successfully canceled close may reuse its already reserved requote cycle once for a same-direction replacement; an exhausted protective cancellation waits for new quota. The Lighter pre-sign guard runs after its write lock and nonce await; a proven unsent deferral spends no zero-fill retry. An unsent reserved nonce is returned through the existing nonce manager; failure to return it retires the writer and fails closed. Every 30 seconds an authoritative idle position snapshot is reconciled. Read errors are never interpreted as flat positions. Drift greater than one common size step creates a durable correction obligation through the same hedge path. Before each corrective send, a fresh account snapshot must pass both venues' projected gross, reservations and equity caps. Failure halts, cancels makers and preserves the uncovered obligation; no stale snapshot is applied while fills/hedges are in flight.

## Execution diagnostics

Market-health alarms use the same public/private validity classification as `market_stale`: `reason` is `connection_timeout`, `sequence_gap`, `generation_change` or `reconnect`, with venue, boot/episode, original start and elapsed seconds. The same episode is throttled for 30 seconds independently of engine state; recovery clears that throttle, and repeated alarms retain the original start. `diagnostic_source` distinguishes public/private validity from a legacy book-only fallback. Without socket-validity evidence, a missing, old or future-dated book is an `unclassified` alarm with a book-only detail and first-observation age; it does not create one of the four socket stale categories. Explicit generation mismatch remains classified, with unavailable episode history marked `age_source=first_observed`. An unhealthy transport with no classified market failure is explicitly unclassified. Ordinary risk/hedge alarms and the first halt cause retain their existing behavior.

Each prepared close intent records one `close_quote`: legal EMA price, raw floor/cap, final price, side/quantity, oldest attributable FIFO opening time/age, and estimated whole-quantity two-leg profit percent. `mode=floor` means the fresh selected portions have known costs; `mode=cost_unknown` means some fresh selected cost is missing. `protected_qty`, `cost_unknown_qty`, `expired_qty` and price coverage record the partition. `protection_active` depends on positive known protected quantity in either mode, and `bound_binding` shows whether that bound moves the EMA quote. `mode=ema` means all selected protection has expired or the timeout is zero. The later close maker fill inherits `close_mode=floor|timeout|cost_unknown` from that durable intent, rather than reclassifying a 599-second floor quote that happens to fill after 600 seconds. A remaining opening origin emits `close_floor_timeout` once; unknown origin age is explicitly `observed_at`/`age_source=observation`, never a fabricated `open_at` or actual holding period.

Close requotes record `close_cancel_decision` before cancellation, with the actual floor/quote/anchor reason, old and target prices, executable Lighter reference, Arcus BBO and quota/global pending state. `close_cancel_result` correlates the client with the terminal confirmation result and monotonic time; an unconfirmed cancellation remains unconfirmed. Safe old closes are retained while an unprocessed global ACK queue or uncertain write prevents replacement. Known eligible hedge residuals block only their own symbol; the existing symbol worker waits for that hedge without putting all symbols into HEDGING or making the quote tick wait for network I/O. Confirmed dust can accumulate under the original hedge minimum policy. Recovered uncertain writes, UNKNOWN, exhausted failures and the existing health, capital and reconciliation safeguards retain their global protection. Unsafe floor cancellation still has priority, and replacement rechecks the rolling two-per-second quota after awaits. Safe floor movements obey the existing fair-anchor requote threshold and maximum order age; a protected bound becoming unbounded with a different target still requests one normal requote. If quota or a global blocker delays that release, the prior bound remains cached until replacement can proceed. A confirmed close cancellation that reserved a requote token may retain one process-local replacement permit for that same symbol/side, quantity, inventory and market/private recovery identity. It expires with the original token after one rolling second, is consumed before the first replacement prepare attempt, and never refunds or adds tokens. A temporary ACK queue or pre-prepare guard rejection may delay that one preparation without renewing the permit; lock waits recheck its identity or current ordinary quota before preparation. All existing place and signing guards still apply. Filled/uncertain cancellations, changed inventory/identity, pauses, reconciliation, halt, stop and restart invalidate it. Permit quantities are compared after flooring to the same common execution step used by place; a different effective planned replacement quantity conservatively receives no reusable permit.

`close_quote_wait` records admission waits only for quota, `global_queue`, `global_residual`, `local_residual`, or `other_admission_unknown` after `place` returns no client. Events occur on entry, reason/scope change and exit, with exit duration; changing BBO or remaining quota time does not create another event. `retain_safe_order` means an old safe order remains and is not downtime. `replace_missing_order` describes a missing close awaiting preparation. An exit with `end_reason=prepared` means a durable intent was prepared, not acknowledged or resting; later rejection/UNKNOWN and actual resting uptime remain separate. Flat inventory, changed inventory, unavailable quoting and stopping have distinct exit reasons. These events do not cover every possible cause of a missing order, do not measure ACK latency, and do not change the complete uptime denominator. Diagnostic insert failures emit only a fixed event name and exception type to stderr and cannot block cancellation, preparation or shutdown; existing economic journal failures retain their original behavior. Health pauses and halts end active admission waits immediately, so outage and warmup time is not attributed to a previous quota/global blocker.

Close maker fills initially have null roundtrip PnL and pending status. Confirmed closing hedge allocations enrich only diagnostic JSON fields on that maker event and append a `close_fill_enriched` audit in the same transaction as a durable cursor. The shared FIFO reducer supplies original actual two-leg entry prices and exact confirmed tranches; original event economic fields are unchanged. Partial confirmed/priced/restored quantities and coverage remain explicit. Gross USD is `opening_side * quantity * (Arcus close - Arcus open + Lighter open - Lighter close)`; unknown actual prices remain null, and restored amounts do not count as roundtrips. Crash/restart repeats neither audits nor completed roundtrips. Archived identities remain available without current-only joins.

Hourly/daily reports include every observed enabled symbol even without fills. Quote uptime is the union of confirmed resting maker orders with positive remaining quantity; prepared intents and transport ACKs alone do not qualify. Its denominator is the complete observed runtime including warmup, stale pauses and periods without orders. Checkpoints bound a crashed run at its last observation; UTC boundaries split durations. Paper/monitor uptime is explicitly modeled resting uptime, not real exchange order evidence. `stale_counts` and `stale_seconds_by_reason` distinguish connection timeout, sequence gap, generation change and reconnect; overlapping venue intervals aren't double-counted in symbol stale seconds, and shared socket episode IDs prevent four symbols multiplying the global count.

Roundtrips count a unique close obligation once when fully resolved with some confirmed hedge quantity; `close_floor_count`/`close_timeout_count`/`close_cost_unknown_count` count those completed obligations by durable intent mode, not unfilled quote intents or hedge fragments. Gross four-leg PnL enters the period when each confirmed tranche completes. `roundtrip_pnl_usd` is a gross alias of `roundtrip_gross_pnl_usd`; neither subtracts unknown fees or funding. `stale_events` is the total episode count and `stale_events_by_reason` aliases the four-reason `stale_counts` mapping. Stale intervals and episode deduplication are scoped to their process boot, including unrecovered shutdown/crash intervals. Reports show pending/unpriced/restored coverage, quantity-weighted actual holding time (only known opening times), notional-weighted actual opening/closing edges and signed Lighter hedge slippage (positive is worse). `pnl_per_10k_arcus` divides gross PnL by that period's reported Arcus maker plus emergency actual notional, with its denominator and coverage reported explicitly; absent or incomplete samples yield null ratios. Fees/funding keep their existing independent coverage and are never silently zeroed. Gross estimates and actual gross PnL are not net profit.

Fill event JSON retains its obligation ID. Archive-aware symbol lookup uses `SELECT m.symbol FROM all_obligations o JOIN all_orders m ON m.client=o.maker WHERE o.id=?` (also exposed by `Journal.obligation(id)`), so physical archival cannot lose fill-symbol attribution. Symbol is additionally retained in the event's `symbol` column; no current-only order join is needed.

## Durability and failure behavior

`run/maker-taker/{paper,replay,live}.sqlite` stores intent, unique client identities, reservations, cumulative fill watermarks, hedge obligations, attempts, signed transaction hash/nonce metadata and statistics. No private keys, signatures, auth tokens or signed payloads are recorded. Intent is committed before any send. A maker fill watermark and its new obligation are committed in one SQLite transaction.

Duplicate/reordered observations cannot create a second hedge. ACK is not fill; cancel ACK is not terminal. A partial terminal hedge retries only the uncovered remainder. `max_retries: 3` permits the initial attempt plus three retries that end in a confirmed zero-filled Lighter terminal result. Positive terminal partial fills continue only for the remainder and neither consume this budget nor clear earlier zero-fill failures. A shared FIFO attempt is classified by its total filled quantity, not each allocation separately. Timeout/UNKNOWN retains the original identity, cancels makers and reconciles; it never blindly retries or flattens. PREPARED after a crash is potentially sent and is queried rather than retransmitted. Exchange client IDs are only unique while live, not permanent exactly-once keys. Missing history coverage remains UNKNOWN, requiring operator resolution.

Arcus partial fills accumulate durably by symbol, direction and purpose (including close reduceOnly semantics); opposing directions are not netted. A hedge uses `floor(total residual / Lighter step) * step` and sends only when it meets Lighter metadata minBase and `max(10 USDC, metadata minQuote)` at a fresh executable price. This is the user's conservative policy, not a claim that these maker minimums are an exchange IOC minimum. Live signing and paper execution recheck the same function; price changes also reevaluate waiting balances. Small tails wait without spending retries or entering EMERGENCY, and remain in inventory, capital reservations, segment limits and the 500 USDC risk guard. An authoritative matching account snapshot permits startup and further quotes with deferred dust. UNKNOWN writes and exhausted zero-fill failures remain blocked; adding a new fill never resets an earlier obligation's retry budget. The original zero-fill failure count survives positive fills, dust, newly aggregated fills, restart and archival history. The 500 ms hedge target is monitored, not guaranteed.

Schema v3 persists exact Decimal-string current inventory and pending obligation IDs in the same transaction as maker/hedge watermarks. Active orders/attempts and relationship lookups use SQL filters and indexes rather than loading completed history. FIFO allocations retain original identities, references and retry budgets. Known v1/v2 journals undergo exact schema, identity, integrity, amount and relationship validation, then one atomic, linear backfill to v3. Reopening v3 validates its derived state, lifecycle enums and allocator high-water marks against complete history and rejects inconsistencies without repair. Runtime allocators also reject identities already present on either storage side. Deferred attempt flags are updated with attempt state and indexed by obligation, so repeated no-send deferrals do not grow retry checks; complete audit history remains readable.

Every five seconds maintenance runs at most eight small batches, yielding between them. Each batch examines at most 32 candidate makers with a bounded graph-work budget and a 256-node component limit; zero-fill terminal orders have priority and a rotating cursor also visits filled components. A closed component moves all connected maker orders, obligations, attempts and FIFO allocations into archive tables and deletes them from current tables in one transaction. Every order/attempt must be terminal and every obligation fully covered. Dust, UNKNOWN writes and oversized components remain current; oversized components need a separately planned offline archival operation if their storage becomes material. Hot queries stay bounded by current active/pending state even while historical components remain current. Histories, finance, statistics and known-ID startup recovery include both storage sides. A late maker fill restores its complete archived component transactionally, then applies only the new delta; restoration does not alter inventory or reuse identities. Conflicting terminal hedge quantities still require reconciliation. Events, executions and funding records are retained; archiving does not shrink the overall SQLite file.

Old code cannot open a v3 journal. Preserve the database and unresolved state on rollback, and restore only compatible code; never delete the journal to bypass a halt. For a backup while SQLite is active, use SQLite's backup API rather than copying a live WAL database.

The first halt cause is recorded once in a journal `halt` event with its state, symbol and process boot. Runtime and final JSON retain `halt_reason`, `halt_state`, `halt_symbol` and a whitelisted `halt_error_type`; subsequent alarms remain in `last_alarm` and cannot replace the cause. A latency warning alone does not halt. Generic historical halt events do not introduce a restart lock; the separate severe-failure manual-intervention latch below does.

Shutdown can finish safely with deferred dust or paired holdings. Its output includes `pending_residuals` and `positions_flat`; `shutdown_clean` does not mean positions were flattened.

When confirmed zero-fill hedge retries are exhausted, the runner durably locks all new order sends, attempts to cancel every Arcus maker, and preserves positions and unresolved obligations for manual handling. It no longer automatically unwinds an opening fill or restores a closing fill after that failure. An emergency action that is rejected, uncertain, partially incomplete, or cannot legally proceed because of size, capacity, capital, cancellation or existing UNKNOWN state applies the same policy. Ordinary deferred dust and ordinary quote admission rejection remain ordinary waiting conditions. A failed cancellation remains explicitly unresolved; the lock does not claim that every order was canceled.

The first severe-failure snapshot is stored atomically in existing journal metadata, a `manual_intervention` event, and one `halt` event carrying that complete severe-failure snapshot, separately from the generic first halt cause. Runtime and final JSON expose `manual_intervention_required`, the durability flag `manual_intervention_persisted`, and `manual_intervention_snapshot`, including the failure symbol, fixed reason/code, signed Arcus and Lighter quantities, signed net exposure and unresolved quantity. Known quantities are Decimal strings describing the confirmed ledger at that moment. Failed inventory reads produce null quantities with explicit inventory coverage; failed emergency accounting leaves unresolved quantity null rather than guessing zero. The send lock takes effect before those reads or writes, and failure handling still attempts global maker cancellation. Already-sent requests can still fill: cancellations, original-identity lookups and authoritative late fills remain enabled and record subsequent position changes, without starting another hedge or correction. Unknown acceptance and uncovered exposure still require manual reconciliation; stopping is not evidence that positions are flat.

The lock survives restart and blocks new maker, hedge, correction and emergency sends, including after signing-lock/authentication waits and paper execution latency. Stop and recovery preserve it. No automatic reset or unlock command is provided: reconcile both venues and obtain explicit authorization for any later recovery work. A failed metadata transaction reports an error and leaves the current process unable to send, but must not be described as successfully persisted. Preserve the journal and investigate storage failures. Rolling back to older code may ignore this metadata lock; rollback is not an authorized way to release manual intervention. Final failure status uses the cached manual-intervention state even if stop or SQLite reads/writes fail. Task, transport, market-source and journal cleanup are attempted independently; cleanup errors report only their stage and exception type. An incomplete stop or cleanup reports `shutdown_clean: false` and a nonzero exit, preserving the original failure snapshot.

## User-run live acceptance

Use dedicated Arcus and Lighter accounts for this strategy. Set each venue's UI leverage to **at most 2** before running. Returned authoritative leverage is checked when available; an unavailable setting API is reported as unverified. The runtime equity/gross-notional cap is a separate enforced boundary and does not set venue leverage.

Put credentials in this project's root `.env` (or supply `--env-file /absolute/path`); only explicit live/taker mode reads it. No credential YAML is needed. Keep the file private:

```dotenv
ARCUS_API_KEY=
ARCUS_API_SIGNING_KEY=
ARCUS_WALLET_ADDRESS=
ARCUS_ACCOUNT_INDEX=0
LIGHTER_API_KEY_PRIVATE_KEY=
LIGHTER_ACCOUNT_INDEX=0
LIGHTER_API_KEY_INDEX=0
LIGHTER_VERIFY_SSL=true
```

```bash
chmod 600 .env
# One segment; each flat side meets both venue minimums and the conservative 10 USDC hedge policy.
bash start.sh live --small-live --duration-seconds 86400
```

For a server session that survives closing SSH, start one of these modes at a time:

```bash
tmux new -s arcus-maker-paper 'bash start.sh monitor --duration-seconds 86400'
tmux new -s arcus-maker-live 'bash start.sh live --small-live --duration-seconds 86400'
# Detach: Ctrl+B, then D. Reattach the session you started:
tmux attach -t arcus-maker-paper
tmux attach -t arcus-maker-live
```

Live endpoints are fixed official mainnet HTTPS/WSS with verified TLS. No authentication is sent to configurable destinations. HTTP and WebSocket redirects are rejected; a redirected write remains UNKNOWN. The runner takes a journal lock and separate shared locks for each venue account across its checkouts/state paths; changing the paired venue or API key cannot evade an existing account lock. Older projects do not implement these shared locks: dedicated accounts are mandatory, and a project lock cannot prevent an older process from using the same account.

SIGINT/SIGTERM stops admission, cancels makers, drains known obligations, flushes the journal/statistics and disconnects within a bounded shutdown. Nonzero exit plus alarms means cancellation/hedging remains unresolved. Preserve the journal and inspect both venues' orders/positions before restarting or changing code. Never delete a live journal to bypass UNKNOWN. Startup cancels legacy Arcus orders and requires authoritative reconciliation before new quotes. Unknown legacy fills or unsupported positions can require manual resolution.

Code rollback: stop and reconcile first, preserve the journal and its backups, then restore code compatible with that schema. Switching to taker_taker while maker orders remain is forbidden. A code rollback cannot itself unwind exchange positions.

## Replay and validation

Paper Lighter IOC matching consumes all published levels inside the same native 0.1% price bound used by live signing (buy ceiling / sell floor in native price units). It floors aggregate fills to the Lighter lot step and reports their volume-weighted average price. Repeated attempts share the remaining liquidity of that exact immutable snapshot; a new published snapshot refreshes it. Fixtures without depth conservatively expose only their BBO sizes. This is a simulation, not a claim of queue position or real exchange liquidity.

The included replay is synthetic, uses protocol-shaped public metadata, and simulates 60 seconds of continuously refreshed two-venue books through the production warmup gate. It is distinct from 24-hour public-market paper evidence:

```bash
.venv/bin/python run_maker_taker.py --mode replay \
  --replay tests/fixtures/maker_taker_replay.json --state-dir /tmp/arcus-maker-replay
.venv/bin/python -m pip install -r requirements-test.txt
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -q -p no:cacheprovider tests/test_maker_taker*.py
bash -n start.sh
```

Hourly/daily JSON projections show maker/hedge/emergency volume, actual reported fee coverage, signed hedge slippage, peak uncovered exposure, requotes and monotonic receive-to-confirmation latency p50/p95/count. Simulation rows are labeled modeled. Hourly reports run in a fresh interpreter with a read-only SQLite connection and a consistent snapshot, so Python history processing cannot contend for the trading interpreter lock. The child receives only a journal path and period, with a small environment whitelist and closed inherited file descriptors; a five-minute timeout or cancellation terminates and reaps it. Report failures remain explicit. Final reports run sequentially after maker shutdown. The asynchronous live collector yields during batched history reads and pages through both venues' actual trades/funding histories and durably deduplicates records. Arcus actual fee amounts and funding `payment` are supported (positive payment is received, so cost is its negative). Inclusive microsecond page boundaries overlap; a saturated same-time page or conflicting record prevents a complete-coverage claim.

Lighter's public API/SDK does not define monetary units for integer trade fee fields, or bind funding `change`/`discount`/timestamp to unambiguous amount/sign/time units. Its collector fetches all cursor pages without guessing time-filter units, preserves whitelisted raw values and reports separate transport and semantic coverage. Reasons include `fee_semantics_unverified`, `change_sign_unit_unverified`, `discount_semantics_unverified` and `timestamp_unit_unverified`. It never divides an integer fee by a guessed scale or reconstructs actual funding from rates. See the official [positionFunding reference](https://apidocs.lighter.xyz/reference/positionfunding), [PositionFunding SDK model](https://github.com/elliottech/lighter-python/blob/main/docs/PositionFunding.md) and [Trade SDK model](https://github.com/elliottech/lighter-python/blob/main/docs/Trade.md).

Missing actual fees/funding, unresolved semantics or incomplete valuation make total cost and cost-per-10000 unavailable. Both combined-venue and maker-volume denominators are shown when complete; emergency cost is included in total. No fee tier, profitability, cost below 0.5 USDC/10000, 24-hour reliability or P95 below one second is established by offline tests. Actual Lighter monetary-cost acceptance remains unavailable until those API semantics are authoritatively confirmed.

Public-data testing from this development environment reached all four Arcus WebSocket subscriptions. Lighter's official WebSocket endpoint returned code `20558`, restricted jurisdiction, before subscription. The implementation does not bypass this restriction. Real Lighter WebSocket readiness, full ACTIVE operation and the 24-hour runs require the user's permitted server environment; offline fixtures do not establish those outcomes.

The legacy taker_taker executor is retained behind explicit dispatch and its own preserved profile:

```bash
bash start.sh taker_taker --config config/arbitrage/arbitrage_taker_taker.yaml
```

That command starts the retained profile in its historical read-only mode. To use the old live executor, copy the legacy profile and explicitly set `system_mode.monitor_only: false` in that copy, then pass the copy with `--config`. First stop the original account owner, resolve all maker obligations and verify both venues' positions/open orders before switching. The legacy executor retains its historical stop semantics and is not the public-only maker paper path. Never run both owners against the same accounts.
